- src/server.ts               Lazy Storefront per principal (Map<walletId, Promise<Storefront>>), wallet id
                              "customer:<id>" (legacy wallet id may not use that prefix), budget/email from
                              identity record; await state.ensureSession before constructing.
                              MCP sessions bound to principalId; foreign session id -> 404 (same as unknown);
                              auth checked on every request (revocation is immediate locally).
                              Per-principal session cap (BODEGA_MAX_MCP_SESSIONS_PER_PRINCIPAL, default 10)
                              evicts that principal's own oldest session.
                              Proxy keys resolved globally via state.resolveToken/consume (bearer capability);
                              use/buy stay principal-scoped through each Storefront.
                              /mpp authenticates X-Bodega-Agent-Token per principal and uses that principal's

                              Webhooks look up attempt by payment/purchase id, resolve owner via

                              /admin/approvals lists pending approvals across legacy + all customers with
                              customer_id/approver_email. isAdmin refuses if admin token == agent token.
                              /health reports identity backend + whether credentials are required.
                              All state.* calls in server.ts are awaited (compatible with async WalletStore).
                              store/wallet.ts and store/storefront.ts NOT modified.
- src/main.ts                 Non-loopback binding allowed with a >=24 char legacy token OR per-customer

Env
- BODEGA_IDENTITY_BACKEND=sqlite|insforge (insforge requires INSFORGE_URL + INSFORGE_API_KEY, else startup throws)
- BODEGA_IDENTITY_DB_PATH (sqlite path; ":memory:" automatically when wallet is ":memory:")
- BODEGA_REQUIRE_AGENT_AUTH=1 disables anonymous legacy access (implied by insforge)
- BODEGA_AUTH_CACHE_MS positive auth cache (default 5000 for insforge, 0 for sqlite, max 60000); cleared
  locally on any admin mutation. Other replicas may honor a revoked token for up to this window.
- BODEGA_MAX_MCP_SESSIONS_PER_PRINCIPAL (default 10)
- createApplication({ identity, identityPath }) injection seam for tests.

Known limitations / follow-ups
- Budget changes after creation are not exposed: WalletStore.ensureSession is insert-or-ignore, so a cap
  edit in the identity table would not reach the wallet. Add a wallet policy update in wallet.ts first.
- Wallet/attempts remain in local SQLite (or whatever the async WalletStore worker provides); identity
  can be remote. Approval links show the wallet id ("customer:<id>") to the approver.
- Storefront cache is unbounded but limited to admin-provisioned customers.
- No public signup/passwords; no notifications/Connect (root owns those).
